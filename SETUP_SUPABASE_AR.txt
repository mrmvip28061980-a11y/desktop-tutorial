تشغيل الطلبات المشتركة مع GitHub Pages (مهم: نفّذ الخطوات مرة واحدة)

لماذا يلزم هذا؟
GitHub Pages يستضيف ملفات الموقع فقط ولا يشغّل server.js. هذا الإصدار يستخدم Supabase كقاعدة بيانات خارجية، ويبقى الموقع منشورًا على GitHub Pages.

1) أنشئ مشروعًا على https://supabase.com/ وسجّل الدخول. احتفظ باسم المشروع.
2) افتح SQL Editor داخل مشروع Supabase، وافتح ملف supabase_setup.sql الموجود داخل هذا الملف المضغوط، وانسخ كل محتواه ثم اضغط Run. هذا ينشئ جدول الطلبات وسياسات تمنع الزوار من قراءة بيانات العملاء.
3) من Supabase: Project Settings > API. انسخ Project URL و anon/public key (لا تستخدم service_role key أبدًا في الموقع).
4) افتح supabase-config.js واستبدل YOUR_PROJECT_ID داخل الرابط بعنوان مشروعك، واستبدل YOUR_SUPABASE_ANON_PUBLIC_KEY بالمفتاح العام anon. احفظ الملف.
5) من Supabase > Authentication > Users، أنشئ مستخدمًا للأدمن ببريد إلكتروني وكلمة مرور. أنشئ حسابات الأدمن بنفسك فقط، ولا تفعّل التسجيل العام للمستخدمين. هذه بيانات دخول لوحة الإدارة الجديدة.
6) ارفع كل ملفات الموقع إلى مستودع GitHub نفسه، بما فيها supabase-config.js وsupabase_setup.sql وSETUP_SUPABASE_AR.txt. انتظر تحديث GitHub Pages.
7) افتح الموقع، اضغط دخول الإدارة، واستخدم بريد وكلمة مرور مستخدم الأدمن الذي أنشأته في الخطوة 5.

بعد الإعداد:
- العميل يستطيع إرسال طلب جديد، ويُحفظ في قاعدة البيانات المشتركة.
- الأدمن المسجل دخوله يستطيع رؤية كل الطلبات من أي جهاز وتغيير الحالة إلى مقبول أو مرفوض.
- قائمة الطلبات تتحدث تلقائيًا كل 12 ثانية أثناء فتح لوحة الإدارة.
- الزوار لا يستطيعون قراءة تفاصيل الطلبات؛ القراءة والتعديل والحذف متاحة لحسابات Supabase المسجلة فقط.

مهم جدًا للأمان:
- لا تضع service_role key في supabase-config.js. المفتاح الوحيد المسموح به هنا هو anon/public key.
- لا ترفع بيانات دخول الأدمن إلى GitHub ولا تشاركها مع العملاء.
- كلمة المرور القديمة الثابتة (mazen) لم تعد طريقة تسجيل الدخول؛ استخدم حساب Supabase للأدمن.
- إعداد Supabase مطلوب قبل أن تعمل الطلبات المشتركة. لا يمكن إكمال الربط الحقيقي من دون إنشاء مشروع قاعدة بيانات في حسابك، لأن ذلك يحتاج صلاحية دخول لحسابك.
